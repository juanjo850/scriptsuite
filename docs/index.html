scriptsuite scans a script/ folder, lists everything runnable in a sidebar, runs the selected script in a real pseudo-terminal, and streams its output and stdin interaction back while you watch. The right pane holds that script's arguments and declared options; the bottom pane holds its source.

Why

Running a test script usually means leaving the editor, remembering the flags, and reading output in a terminal you cannot navigate. scriptsuite is one screen for that: the scripts you have, what each one accepts, what it just printed, and its source — with the run happening in the middle.

Install

Requires Linux or macOS (the interactive workspace needs a POSIX pseudo-terminal) and Python 3.11+.

python -m venv .venv
.venv/bin/pip install -e .

The runtime dependencies are Textual and Rich, which Textual uses for rendering.

For the development extras (tests, linting, docs):

.venv/bin/pip install -e ".[dev,docs]"

Once a release is published, pipx install scriptsuite is the recommended way to keep the command on your PATH.

Use

scriptsuite                     # uses ./script, then ./scripts
scriptsuite path/to/scripts     # explicit folder
scriptsuite --list              # print what was discovered, then exit
Option Meaning
DIR / -s, --scripts-dir scripts folder to scan
-p, --python interpreter for Python scripts (default: the one running scriptsuite)
--no-recursive only scan the top level
-V, --version print the version

SCRIPTSUITE_SCRIPTS_DIR sets the folder without a flag. If nothing is found, the interface says which folder it looked at and what it accepts, rather than showing an empty list.

--list exits with 0 when scripts were found, 1 when the folder contains nothing runnable, and 2 when the folder does not exist. The interactive workspace needs a POSIX pty; on Windows, --list still works and the normal launch explains the limitation.

Stdin

Key Action
f2 jump to the input bar (not needed at a prompt)
enter send the line to the script
↑ ↓ recall previous input
f6 raw mode: forward keys verbatim
f6 again leave raw mode
escape give focus back to the list (line mode)

In raw mode Escape, Ctrl-C, function keys, arrows and pasted text are forwarded to the script byte for byte, which is what full-screen programs expect. Press f6 to leave raw mode. f1 and ctrl+q still open help and quit; in line mode the usual editing keys (←/→, home, end, ctrl+u, ctrl+k, …) edit the line, so app shortcuts such as ctrl+a and ctrl+k apply once focus is back on the list.

ctrl+u clear every argument for this script

What it does

Discovers scripts

Everything runnable in the folder, recursively: .py, .sh, .js, .rb, .pl, .exp, .tcl, … An unknown extension is not a veto — if the file carries a #! shebang, the shebang decides how to run it and wins over the extension. Descriptions come from the module docstring, or from the first comment for everything else; files that import pytest/unittest or subclass TestCase are tagged as tests.

Runs them like a terminal would

Each run gets its own pty, so colours, cursor control and progress bars all behave and isatty() is true inside the script. The child runs in its own session, so Ctrl-C reaches the script rather than the interface. Window size changes are pushed down and SIGWINCH is sent, so full-screen programs redraw correctly.

Shows output as it happens

Reads are decoded incrementally: escape sequences split across reads are reassembled and ANSI colour is preserved. A progress bar that repaints with \r collapses onto one line instead of flooding the log, while an unterminated prompt like Enter your name: still appears within ~120 ms. Carriage returns are replayed on the visible text rather than on the escape bytes, so a coloured progress bar collapses to its last value instead of showing fragments of the escape codes.

Summarises results

pytest, unittest and TAP output are parsed into counts and a verdict. The verdict can override a clean exit code, so a suite reporting failures shows as failed even when something masks the exit status; a non-zero exit is never hidden by a passing-looking summary. Failed test names are pulled out for the status line. A script that prints nothing gets no invented numbers, just its exit code.

Sends input both ways

Type a line and press enter to send it to the script's stdin, with history on ↑ ↓. In raw mode every keystroke is forwarded verbatim, for programs that want arrow keys and escape sequences.

Follows the prompt

When a script asks a question, the caret moves to the input bar by itself — no f2. The tell is an unterminated line that stopped changing: a progress bar repaints continuously, so it never looks settled and never steals focus. Focus is only taken from the sidebar or the output; if you have gone to the arguments or the source on purpose it is left alone, and escape means what it looks like — stay there until the next question. When the run ends, focus returns to the list rather than stranding a disabled field.

Shows each script's interface

Every declared argument gets its own control — a text field for values, a checkbox for switches — ordered the way a command line is: positionals, then named options, then whatever is left in the free-form box underneath. Values are remembered per script as you move through the list. The interfaces are read from the source:

  • Python — argparse is parsed with ast, so flags, help text, whether an option takes a value, its choices, its metavar and whether it repeats all come through accurately. Positional arguments get a field each.
  • Expect and Tcl — a cmdline::getoptions block is decoded, including the name.type form, so a spec like {host.arg "" "Target host"} becomes a --host field. Everything is passed with a leading --, which is what the package expects: expect reserves single-dash options for itself. $argv access becomes positional fields.
  • Shell — getopts optstrings are decoded properly; otherwise only long flags that something documents are shown, because a bare -c is more often wc -c than an option.
  • Python without argparse — positional fields, from whichever sys.argv index the script reads.

Where nothing can be found, the pane says so rather than guessing.

Shows the source

The bottom pane holds the highlighted script, syntax highlighted and read-only, with line numbers. Highlighting uses Pygments through Rich, so no tree-sitter grammar is needed; Expect borrows the Tcl lexer, which is what it is. Long lines wrap rather than disappearing behind a horizontal scrollbar, and an oversized file is truncated with a note rather than stalling the interface. f7 expands the pane to fill the workspace when you want to read rather than watch.

Layout

Four regions on plain flex containers, so hiding a pane is a single display: none and its space flows back to its siblings — no grid bookkeeping. The sidebar, arguments pane and source pane each live in their own module under widgets/, mounted from app.py.

The layout tightens on narrow terminals: below 112 columns the side panes shrink, below 92 the right pane is hidden until you ask for it with f9.

Development

.venv/bin/python -m pytest -m "not integration"   # fast: no child processes
.venv/bin/python -m pytest                        # full suite, ~2 minutes
.venv/bin/ruff check src tests tools
.venv/bin/ruff format src tests tools

The pty tests use real pseudo-terminals and are marked integration. CI runs the fast suite on every supported Python on Linux and macOS, then the integration suite with a per-test timeout. Coverage is measured with pytest --cov=scriptsuite.

Regenerating the docs (the docs extra provides markdown_it and pygments):

.venv/bin/python tools/screenshot.py   # docs/screenshot.svg, from the real UI
.venv/bin/python tools/build_docs.py   # docs/index.html, self-contained
Module Responsibility
ansi.py incremental bytes → styled Rich text
discovery.py finding scripts and reading their metadata
options.py reading a script's command-line interface
runner.py the pty, process lifecycle, signals
results.py incremental test-output parsing
app.py layout, run orchestration, keybindings
widgets/ sidebar, output, stdin, arguments, source, header, status

script/ holds sample scripts covering streaming output, an interactive prompt, a pytest run with deliberate failures, and one that declares argparse options so the right pane has something to show.

Troubleshooting

  • scripts folder not found — create script/, pass a folder, or set SCRIPTSUITE_SCRIPTS_DIR.
  • A script is listed but does not start — the interpreter in its shebang (or node, ruby, … for its extension) must be on PATH. Use -p/--python to point Python scripts at a specific interpreter.
  • No colours or a garbled line — ensure TERM is set to a colour-capable terminal. The app sets TERM=xterm-256color for children by default.
  • Windows — the interactive workspace is POSIX-only; scriptsuite --list still works.

Notes

  • One run at a time; starting a new one retires and terminates the previous one, and quitting terminates the active child.
  • Output is capped at 10,000 lines; the source pane is capped at 2,000 lines and 512 KB.
  • The sidebar never auto-scrolls away from a run you are watching.
  • ctrl+a walks the visible list in order and advances even if a script needs to be stopped — it will wait on an interactive script until you stop it. ctrl+shift+k cancels the rest of the sequence.
  • Argument values live in memory for the session, so they reset on restart.
  • Stop sends SIGTERM and escalates to SIGKILL after two seconds.
  • Rescanning (f5) runs in the background and keeps the current selection.
